Remaining steps:

       hubble.ui.enabled=false

{{- else }}

{{- else }}

Mode: PROXY-ONLY — Cilium still owns Hubble UI.

    {{ include "hubble-authz-proxy.fullname" . }}.{{ .Release.Namespace }}.svc.cluster.local:{{ .Values.service.port }}
    upstream: {{ include "hubble-authz-proxy.backendURL" . }}

Installing the chart does NOT put the proxy in the data path. Repoint the
frontend's /api at this Service in the "hubble-ui-nginx" ConfigMap:

    proxy_pass http://{{ include "hubble-authz-proxy.fullname" . }}.{{ .Release.Namespace }}.svc.cluster.local:{{ .Values.service.port }};

then restart the hubble-ui Deployment.

  NOTE: Cilium owns that ConfigMap. A `helm upgrade cilium` rewrites it, which
  silently restores the direct path to the backend and disables filtering
  entirely — no error, nothing crashes, every user simply sees everything
  again. Setting hubbleUI.enabled=true makes this chart own the UI and removes
  that failure mode.

{{- end }}
